# Дедупликация Альтернативных Путей и Исправление Применения λ-Переходов

## Проблемы

При исследовании различных альтернативных путей в PDA симуляторе возникало три проблемы:

1. **Повторяющиеся пути**: Одинаковые пути могли добавляться в список результатов несколько раз
2. **Пути-префиксы**: Неполные пути, которые являются началом других путей, добавлялись отдельно вместо того, чтобы быть удаленными
3. **Неправильное применение λ-переходов**: λ-переходы применялись даже когда входная строка не пуста, что приводило к ошибочным состояниям вроде "переход применен, хотя его нельзя применять"

Это приводило к:
- Повторению одинаковых путей в списке альтернативных ветвей
- Показу неполных путей (заканчивающихся посередине) вместе с полными путями
- Неправильному подсчету количества уникальных путей
- Применению λ-переходов в недопустимых ситуациях (когда входная строка еще не полностью обработана)
- Запутанности пользователя при просмотре результатов

## Решение

### Часть 1: Контроль над λ-переходами

Изменена логика применения λ-переходов. λ-переход должен применяться **ТОЛЬКО когда входная строка полностью обработана** (`input === ''`).

**Правильная семантика PDA:**
- Когда `input === ''`: Пытаемся применить λ-переходы для завершения
- Когда `input !== ''`: λ-переходы вообще не применяются, ищем обычные переходы для текущего символа

**До исправления (НЕПРАВИЛЬНО):**
```javascript
const possibleTransitions = this.findTransitions(state, currentSymbol, stackTop);
const lambdaTransitions = this.findTransitions(state, 'λ', stackTop);
const allTransitions = [...possibleTransitions, ...lambdaTransitions];
// λ-переходы применялись даже когда input !== ''!
```

**Пример проблемы:**
- Состояние q1, input "bbaao", стек [Z]
- Пытается применить λ-переход (q1, λ, Z) хотя input не пуста!
- Результат: ошибочный переход

**После исправления (ПРАВИЛЬНО):**
```javascript
// Когда input === '' (строка полностью обработана)
if (input === '') {
  const lambdaTransitions = this.findTransitions(state, 'λ', stackTop);
  // Пробуем λ-переходы
}

// Когда input !== '' (есть еще символы для обработки)
const currentSymbol = input[0];
const possibleTransitions = this.findTransitions(state, currentSymbol, stackTop);
// Ищем ТОЛЬКО обычные переходы, λ-переходы НЕ применяются!
```

Теперь λ-переходы применяются только когда:
- `input === ''` (входная строка полностью обработана)
- Есть λ-переходы для текущего состояния и вершины стека

Это соответствует стандартной семантике PDA.

### Часть 2: Дедупликация путей

Добавлены три метода в класс `PDASimulator`:

### 2.1. `serializePath(path)`
Преобразует путь в уникальную строку-идентификатор для сравнения:
```javascript
serializePath(path) {
  return path.map(step => 
    `${step.state}|${step.input}|${(step.stack || []).join(',')}|${step.status}`
  ).join('::');
}
```

Включает в идентификатор:
- Текущее состояние (state)
- Оставшуюся входную строку (input)
- Содержимое стека (stack)
- Статус шага (status)

### 2.2. `isPathPrefix(shortPath, longPath)`
Проверяет, является ли один путь префиксом (началом) другого:
```javascript
isPathPrefix(shortPath, longPath) {
  if (shortPath.length >= longPath.length) return false;
  
  for (let i = 0; i < shortPath.length; i++) {
    const shortStep = shortPath[i];
    const longStep = longPath[i];
    
    if (shortStep.state !== longStep.state ||
        shortStep.input !== longStep.input ||
        (shortStep.stack || []).join(',') !== (longStep.stack || []).join(',') ||
        shortStep.status !== longStep.status) {
      return false;
    }
  }
  
  return true;
}
```

Если путь 1 является префиксом пути 2, это означает, что путь 1 был бы продолжен в пути 2, если бы его исследование продолжилось.

### 2.3. `deduplicatePaths(allPaths)`
Удаляет дубликаты и пути-префиксы из списка путей:
```javascript
deduplicatePaths(allPaths) {
  // Шаг 1: Удаляем точные дубликаты
  const seenPaths = new Set();
  const uniquePaths = [];
  
  for (const pathObj of allPaths) {
    const serialized = this.serializePath(pathObj.path);
    if (!seenPaths.has(serialized)) {
      seenPaths.add(serialized);
      uniquePaths.push(pathObj);
    }
  }
  
  // Шаг 2: Удаляем пути-префиксы других путей
  const result = [];
  for (const pathObj of uniquePaths) {
    let isPrefixOfAnother = false;
    
    for (const otherPathObj of uniquePaths) {
      if (pathObj === otherPathObj) continue;
      if (this.isPathPrefix(pathObj.path, otherPathObj.path)) {
        isPrefixOfAnother = true;
        break;
      }
    }
    
    if (!isPrefixOfAnother) {
      result.push(pathObj);
    }
  }
  
  return result;
}
```

## Применение

В методе `simulate()` после исследования всех путей:
```javascript
const uniquePaths = this.deduplicatePaths(allPaths);

return {
  accepted: result.accepted,
  path: result.accepted ? result.path : (uniquePaths.length > 0 ? uniquePaths[0].path : initialPath),
  allPaths: result.accepted ? [] : uniquePaths,  // <- используются уникальные пути
  reason: result.reason
};
```

## Результат

✅ Точные дубликаты удаляются (одинаковые пути не повторяются)
✅ Пути-префиксы удаляются (неполные пути, начинающиеся также как полные, не показываются)
✅ Правильный подсчет количества уникальных альтернативных путей
✅ Пользователь видит только полные и независимые пути без дубликатов
✅ Не показываются пути, которые заканчиваются посередине (они являются префиксами других путей)

## Результат применения исправлений

✅ λ-переходы больше не применяются когда входная строка не пуста
✅ Ошибочные состояния типа "переход применен, но нет дальнейших переходов" уходят
✅ Точные дубликаты удаляются (одинаковые пути не повторяются)
✅ Пути-префиксы удаляются (неполные пути, начинающиеся также как полные, не показываются)
✅ Правильный подсчет количества уникальных альтернативных путей
✅ Пользователь видит только валидные и независимые пути без дубликатов

## Тестирование

Проверены различные сценарии:
- **Палиндромы с несколькими вариантами распределения символов** (например: "aabbaa")
- **Отклоняемые строки** (например: "aabbaab", "aabbaao")
  - λ-переходы больше не применяются когда есть еще входная строка
  - Показывается сообщение "Нет подходящего перехода" вместо ошибочного применения λ-перехода
  - Показываются только полные ветви исследования, неполные пути-префиксы удаляются
- **Грамматики с недетерминизмом** - множественные переходы для одного состояния и символа обрабатываются корректно
- **Строки, где один путь является началом другого** - короткий путь удаляется, показывается только полный путь

## Примеры

### Пример 1: Строка "aabbaao" (отклоняется)

Переходы:
1) (q0, a, Z) = {(q0, aZ)}
2) (q0, b, Z) = {(q0, bZ)}
3) (q0, a, a) = {(q0, aa), (q1, λ)}
4) (q0, a, b) = {(q0, ab)}
5) (q0, b, a) = {(q0, ba)}
6) (q0, b, b) = {(q0, bb), (q1, λ)}
7) (q1, a, a) = {(q1, λ)}
8) (q1, b, b) = {(q1, λ)}
9) (q1, λ, Z) = {(q2, λ)}

**Одна из ветвей до исправления (НЕПРАВИЛЬНО):**
- Шаг 3: Применили (q0, a, a) → (q1, λ), теперь q1, input="bbaao", stack=[Z]
- Шаг 4: **ОШИБКА** - применяет (q1, λ, Z) → (q2, λ) хотя input не пуста!

**Та же ветвь после исправления (ПРАВИЛЬНО):**
- Шаг 3: Применили (q0, a, a) → (q1, λ), теперь q1, input="bbaao", stack=[Z]
- Шаг 4: Ищет переход для 'b' - не находит (q1, 'b', Z)
- Шаг 4: Корректно отображает: "Нет подходящего перехода для (q1, b, Z)"
- λ-переход (q1, λ, Z) не применяется потому что input не пуста!

### Пример 2: Строка "aabbaab" (отклоняется)

**Результат:**
- Вместо множества путей-префиксов, заканчивающихся в разных местах
- Показываются только те полные пути, которые не являются началом других путей
- Каждый показанный путь - это самостоятельное исследование ветви

Все пути теперь отображаются корректно, без дубликатов, с правильным применением λ-переходов.
